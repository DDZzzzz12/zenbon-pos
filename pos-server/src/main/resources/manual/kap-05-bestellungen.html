Kapitel 05 – Bestellungen aufnehmen

Nach dem Antippen eines Tisches können Bestellungen aufgenommen werden. Ein freier Tisch wird erst mit dem Senden der ersten Bestellung belegt (siehe Kapitel 04). Produkte werden über das Suchfeld (Artikelcode) oder über das Produktraster erfasst.

Produkt-Tastatur-Modus

Für erfahrene Bediener: Produkte über Suche oder Artikelcodes eingeben.

  • Code direkt eingeben, z. B. P01
  • Mengenangaben voranstellen: 2*P01 für 2 Stück
  • Bestätigung mit Enter oder dem Hinzufügen-Button

Produkt-Raster-Modus

Visuelles Grid mit Kategorie-Auswahl:

  1. Kategorie aus oberer Leiste wählen
  2. Produkt im Raster antippen
  3. Bei Mehrfachauswahl wird die Menge automatisch erhöht

Optionen / Zusätze hinzufügen

  • Optionen werden über Auswahlgruppen (Choice Groups) am Produkt konfiguriert – siehe Choice Groups
  • Erscheinen im Konfigurator nach Produktauswahl; Pflichtgruppen öffnen ihn automatisch
  • Mehrfachauswahl je nach Min/Max-Regel der Gruppe möglich
  • Nachträglich über die Bestellposition bearbeitbar
  • Der Preis-Aufschlag hängt an der Platzierung (Gruppe × Option), nicht am Extra selbst
Frühere flache Extras: Die alte Direktzuweisung (ProductExtrasAssignmentTable) ist im Bestellschirm nicht mehr auswählbar. Migration V84 (Update auf v1.1.0) hat die betroffenen Produkte auf eigene „Extras - <Produkt>“-Gruppen mit unveränderten Preisen umgestellt. Historische Bestellungen bleiben durch die Snapshots exakt erhalten.

Bestellposition bearbeiten

Über das Fenster Artikel bearbeiten können einzelne Positionen angepasst werden. An einer Bestellstation fehlen Individueller Preis und Rabatt; dort wird zum Listenpreis gebucht.

AktionBeschreibung
Menge ändernNeuen Wert eingeben
Individueller PreisEigenen Einzelpreis setzen – wenn das Produkt einen freien Preis erlaubt (allowCustomPrice) oder der Mitarbeiter die Berechtigung Preis überschreiben (PRICE_OVERRIDE) hält
RabattProzentrabatt in ganzen Prozent. Bis 20 % darf jeder Mitarbeiter gewähren; ein höherer Rabatt erfordert die Berechtigung Rabatt gewähren (DISCOUNT_GRANT). Ein ungültiger Wert wird rot markiert, Speichern bleibt gesperrt und der Gesamtpreis zeigt die Position ohne Rabatt
Zum MitnehmenAußer-Haus-Kennzeichen für die MwSt.-Berechnung
NotizFreitext, z. B. „ohne Zwiebeln“
Optionen ändernAuswahlgruppen-Optionen hinzufügen oder entfernen
StornierenPosition stornieren (Grund erforderlich)
Manager-Freigabe: Fehlt eine dieser Berechtigungen, kann ein Manager per PIN aushelfen. Die PIN leiht nur die eine benötigte Berechtigung, nur auf diesem Gerät und nur für den anfragenden Mitarbeiter – nicht alles, was der Manager darf. Ein geliehenes Rabatt gewähren oder Preis überschreiben gilt dabei nicht nur für die Kasse, sondern auch für die Prüfung des Servers beim Absenden der Bestellung; im Prüfprotokoll steht die Bestellung unter dem Namen des Kassierers, mit dem freigebenden Manager als zweitem Namen. Stornierung

Die Stornierung einer Bestellposition erfordert die Angabe von Artikel-IDs und einer Begründung. Stornierungen werden in der CancellationTable protokolliert und mit der TSE verknüpft.

Wer die Berechtigung Position stornieren (ORDER_ITEM_CANCEL) hält oder sie per Manager-PIN geliehen hat, storniert sofort. Alle anderen lösen eine Genehmigungsanfrage aus: Die Stornierung wird erst ausgeführt, wenn ein Manager sie bestätigt.

Grund (Pflicht): Die Kasse verlangt für jede Stornierung einen Grund. Er wird per Antippen gewählt – Falscher Artikel erfasst, Gast hat es sich anders überlegt, Küchenfehler, Nicht vorrätig, Doppelt erfasst – oder unter Sonstiges frei eingegeben. Gespeichert wird immer der deutsche Text, unabhängig von der Sprache der Kasse; bei Sonstiges der eingegebene Text (höchstens 500 Zeichen). Ohne Grund lehnt auch der Server die Anfrage ab (400).

Hinweis: Jede Stornierung wird im Prüfprotokoll festgehalten und ist für die steuerliche Nachvollziehbarkeit nicht löschbar.

Transfer

Bestellpositionen können zwischen Tischen verschoben werden. Dazu werden die gewünschten Artikel-IDs sowie der Zieltisch angegeben. Wie bei der Stornierung wird sofort ausgeführt, wer die Berechtigung Tischsitzung übersteuern (TABLE_SESSION_OVERRIDE) hält oder geliehen hat; sonst entsteht eine Genehmigungsanfrage. Ein freier Zieltisch wird durch den Transfer geöffnet.

Grund (Pflicht): Auch für das Übertragen von Positionen wird ein Grund gewählt: Auf richtigen Tisch verschoben, Rechnung getrennt / getrennte Zahlung, Gast hat Platz gewechselt, Kellnerwechsel oder Sonstiges mit Freitext. Der Grund wird beim Transfer gespeichert (item_transfer.reason, bei älteren Transfers leer) und steht in der Genehmigungsanfrage und im Prüfprotokoll. Ohne Grund antwortet der Server mit 400.
