1. Was sind Choice Groups?

Eine Choice Group (Auswahlgruppe) ist ein wiederverwendbarer Auswahlabschnitt, der an beliebige Produkte angehängt werden kann. Typische Beispiele:

  • Menü-Abschnitte: Entrée / Hauptgang / Dessert — bei einem 3-Gänge-Menü.
  • Größe: Klein / Mittel / Groß — eine Auswahl, Aufpreis je Größe.
  • Add-ons / Beilagen: Extra Käse, Pommes, Sauce — mehrere Auswahlen möglich.

Jede Gruppe legt über Min/Max-Auswahlen fest, ob sie verpflichtend oder optional ist und wie viele Optionen gewählt werden dürfen:

minmaxVerhalten
01Optional, höchstens eine Option (z. B. „Sauce?“)
11Pflicht, genau eine Option (z. B. „Größe“, „Hauptgang“)
0nOptional, mehrere Optionen (z. B. „Add-ons“)
1nPflicht, mindestens eine, höchstens n
Faustregel: verpflichtend ⇔ min ≥ 1  ·  genau-eine ⇔ max == 1.

2. Choice Groups als Administrator anlegen

Die Verwaltung erfolgt im Web-Admin unter Produkte über die Schaltfläche Auswahlgruppen verwalten in der Werkzeugleiste (an der Kasse gibt es keine Artikelverwaltung mehr). Optionen werden aus den bestehenden Extras gespeist — eine Choice Group baut also auf dem bereits gepflegten Extras-Bestand auf.

2.1 Gruppe erstellen (Min/Max)

  1. Unter Auswahlgruppen verwalten eine neue Auswahlgruppe anlegen (Gruppe hinzufügen).
  2. Namen vergeben (optional EN/ZH-Übersetzungen für mehrsprachige Anzeige).
  3. Min-Auswahlen und Max-Auswahlen setzen (siehe Tabelle oben). Es gilt: min ≥ 0, max ≥ 1, min ≤ max.
  4. Gruppe als aktiv/inaktiv schalten. Inaktive Gruppen werden bei der Bestellung nicht erzwungen.

2.2 Optionen hinzufügen (Preis-Delta pro Platzierung)

Innerhalb der Gruppe werden Optionen aus den vorhandenen Extras ausgewählt. Jede Platzierung erhält:

FeldBedeutung
Preis-DeltaAuf- oder Abschlag dieser Option in dieser Gruppe. Das Delta ist pro Platzierung — dasselbe Extra kann in zwei Gruppen unterschiedlich viel kosten.
ReihenfolgeSortierposition der Option in der Gruppe.
StandardVorausgewählte Option beim Öffnen des Konfigurators.
Delta pro Platzierung: Weil der Preis-Aufschlag an der Platzierung (Gruppe × Option) hängt — nicht am Extra selbst — kann „Extra Käse“ in der Pizza-Gruppe +1,50 und in der Burger-Gruppe +1,00 kosten.

2.3 Gruppen an Produkte anhängen

Im Produkt-Editor des Web-Admin werden die fertigen Gruppen einem Produkt zugewiesen (Abschnitt „Auswahlgruppen“, Gruppen zuweisen; ein neues Produkt muss dazu zuerst gespeichert sein). Für eine ganze Kategorie geht das im Kategorie-Editor unter „Auswahlgruppen für alle Produkte dieser Kategorie“ (Zu allen hinzufügen / Von allen entfernen). Die Reihenfolge der angehängten Gruppen bestimmt die Reihenfolge im Konfigurator. Eine Gruppe kann an beliebig viele Produkte angehängt werden — einmal pflegen, mehrfach verwenden.

3. Preismodell

Der Zeilenpreis einer Bestellposition berechnet sich aus dem Grundpreis (oder einem individuellen Preis) plus der Summe der gewählten Options-Deltas, danach rabattiert:

Zeilenpreis = (Grundpreis bzw. individueller Preis
              + Σ(gewähltes Options-Delta × Menge))
              × Rabatt
BeispielWert
Grundpreis18,90
Option „Salmon“ (Delta +3,00, Menge 1)+3,00
Rabattkein
Zeilenpreis21,90
Der Server ist maßgebend. Der Client zeigt eine Live-Vorschau mit derselben Formel, aber der Server berechnet den endgültigen Preis aus dem hinterlegten Delta neu und validiert Min/Max je Gruppe. Eine manipulierte oder veraltete Client-Auswahl wird serverseitig abgelehnt (CHOICE_SELECTION_INVALID) — auch eine Bestellposition, die für ein Produkt mit Pflichtgruppe gar keine Auswahl mitschickt.

4. Bestellung — der Konfigurator

Beim Hinzufügen eines Produkts mit Choice Groups öffnet sich der Konfigurator (das wiederverwendete Bearbeiten-Panel):

Produkt hat …Verhalten
mind. eine Pflichtgruppe (min ≥ 1)Der Konfigurator öffnet automatisch beim Antippen des Produkts.
nur optionale GruppenAntippen fügt direkt hinzu; der Konfigurator wird per langem Druck geöffnet.

Der Konfigurator erzwingt die Min/Max-Regeln jeder Gruppe: Eine Pflichtgruppe muss erfüllt sein, bevor die Position bestätigt werden kann; Maximalgrenzen verhindern weitere Auswahlen. Die Live-Vorschau zeigt den resultierenden Zeilenpreis.

5. Snapshots & Belegtreue

Sobald eine Position verkauft wird, werden die gewählten Optionen als Snapshot auf der Bestellposition gespeichert — jeweils mit:

  • Options-Name (Bezeichnung zum Verkaufszeitpunkt),
  • Preis-Delta,
  • Gruppenname,
  • Gruppen-ID,
  • Menge.
Gruppenname vs. Gruppen-ID: Der Gruppenname ist die belegrelevante Beschriftung und wird nie nachgeschlagen. Die Gruppen-ID dient allein der Wiederauflösung: Wird eine erfasste Position später erneut eingereicht (Nachbestellung, Splitten, Bearbeiten nach dem Senden), braucht der Server die Platzierung (Gruppe × Option), um denselben Preis-Aufschlag erneut zu ermitteln — dasselbe Extra kann in mehreren Gruppen unterschiedlich viel kosten. Bei den alten flachen Extras ist sie leer, denn diese hatten keine Gruppe.

Dadurch driften historische Belege nie, wenn Optionen später umbenannt, umpreist oder gelöscht werden:

VerbraucherQuelle
Belege / KassenbonSnapshot der Bestellposition
Nach-Abrechnung / Re-BillSnapshot der Bestellposition
DSFinV-K Unterpositionen (Bonpos_Zusatzinfo / subitems.csv)Snapshot der Bestellposition
DSFinV-K: Die Unterpositionen (Bonpos_Zusatzinfo) lesen ausschließlich den Snapshot, nicht die aktuelle Options-Definition. So bleibt der Export auch nach späteren Änderungen am Extra reproduzierbar. Siehe DSFinV-K Export §2.4.

6. Migration bestehender Extras

Bereits gepflegte flache Produkt-Extras werden beim Update auf v1.1.0 von Migration V84 automatisch überführt: Jedes Produkt mit zugewiesenen aktiven Extras erhält eine eigene optionale Gruppe „Extras - <Produktname>“ (min 0, max = Anzahl der Optionen). Eine einzige gemeinsame Gruppe wäre falsch — die Zuweisungen waren produktspezifisch, und eine geteilte Gruppe hängte jedem Produkt die Extras aller anderen an.

Das Preis-Delta jeder Option entspricht exakt dem bisherigen product_extras.price — also dem Betrag, der vorher schon berechnet wurde. Durch die Migration ändert sich daher kein einziger Bon-Betrag.

Inaktive Extras werden bewusst nicht übernommen: Ein stillgelegtes Extra soll nicht über den Umweg einer Gruppe wieder auf dem Bestellschirm erscheinen. Produkte, deren zugewiesene Extras sämtlich inaktiv sind, erhalten folglich gar keine Gruppe. Die Zeilen in product_extras_assignment bleiben erhalten — die Migration ergänzt nur, sie löscht nichts.

Bestehende Bestellungen bleiben durch die Snapshots unverändert. Die Verwaltung erfolgt anschließend zentral über Auswahlgruppen verwalten im Web-Admin; im Bestellschirm sind Auswahlgruppen seither der einzige Weg, eine Option zu erfassen.
